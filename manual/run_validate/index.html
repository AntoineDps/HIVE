    run_validate¶

    Runs models against CFD reference data or synthetic wave signals for all (model, wave source, solver) combinations, and saves the simulated time series. Metrics and plots are made afterwards by run_metric on this output folder.

    Run¶

    first run¶

    python -m script.run_validate --case <name>.json

    Config files <name>.json live in inputs/validate_case/. The filename stem becomes the output folder name under out/validated_case/.

    rerun options¶

    When the output folder already exists, the script prompts:

    [1] erase and redo all     — also erases the run_metric results and plots of this folder
[2] stop, do nothing

    what it does¶

    Runs all (model, wave source, solver) combinations. More explicitly:

    1. Loads all model definitions from source/models/<name>/model.json and their HydroSphere
    2. Resolves wave sources — loads the handled CFD cases or generates the synthetic waves (water depth: BEM depth of the models). A warning is printed when the CFD case depth differs from the BEM depth
    3. Checks the solver dt against the CFD reference dt; prompts to continue if they differ
    4. Computes the time margins (t_warmup, t_causal) of every model, and applies the largest to all runs
    5. Runs the full record for every combination, then clips it to the valid time window
    6. Saves the time-series CSVs, the synthetic waves and a copy of each model to out/validated_case/<name>/

    A run that fails (e.g. diverges) is logged with its error and the others continue.

    Input JSON config¶

    {
  "models": [
    {"name": "lin"},
    {"name": "nlfk_x"}
  ],
  "wave_sources": [
    {"type": "cfd_case", "case_name": "test_0_handle_case"},
    {
      "type": "synthetic",
      "wave_type": "irr",
      "T": 6.5,
      "H": 2.0,
      "gamma": 3.3,
      "duration": 150,
      "dw": 0.01,
      "w_end": 8.0,
      "wave_energy_fraction": 0.999
    }
  ],
  "solvers": [
    {"method": "RK4", "dt": 0.05, "interpolation": {"restoring": "linear", "excitation": "linear", "cfd": "linear"}}
  ],
  "eta_inputs": [{"type": "true"}],
  "simulation": [{"type": "closed_loop"}]
}

    All fields are required, and unknown keys are errors.

    Field Type Multiple entry (list) Description
    models dict Yes. All entries are simulated Models to validate. Each dict has exactly a "name" key pointing to a folder under source/models/. See Model
    wave_sources dict Yes. All entries are loaded and run independently Wave elevation sources. See wave_sources
    solvers dict Yes. All entries are run for every (model, wave) pair Simulation solver settings. See Solver. Two solvers with the same method, dt and interpolation are an error
    eta_inputs dict Yes Wave elevation given to the model. Only {"type": "true"} (the measured or generated elevation) is implemented
    simulation dict Yes Simulation type. Only {"type": "closed_loop"} is implemented

    All models × wave_sources × solvers combinations are run automatically. Pass lists to any of the three fields to expand the matrix.

    wave_sources¶

    CFD case — {"type": "cfd_case", "case_name": ...}

    Field Type Description
    type "cfd_case" Wave elevation and reference data from a handled case
    case_name string Handled data folder name under data/handled/. Every case of the folder is run

    The simulation starts from the CFD state at the first time step. A wave-only case (empty basin) starts from rest, and its models need numeric PTO gains.

    Synthetic wave — {"type": "synthetic", ...}

    Field Type Options / values Description
    type "synthetic" — Wave generated as a sum of regular components. No reference data: only the model responses are produced
    wave_type string "reg" · "irr" (JONSWAP) Wave type
    T float s Wave period (regular) or energy period (irregular)
    H float m Wave height (regular) or significant wave height (irregular)
    gamma float | null — JONSWAP peak enhancement factor (null for a regular wave)
    duration float s Signal duration
    dw float rad/s Frequency step of the components
    w_end float rad/s Highest component frequency
    wave_energy_fraction float — Energy fraction of the components kept around the peak

    A synthetic wave has no time step of its own: it is generated once from its components and evaluated on each solver grid, so every solver sees the same wave (a warning is printed if components exceed the Nyquist frequency \(\pi / dt\)). The wave water depth is the BEM depth of the models. The PTO gains come from each model (a synthetic wave has no CFD gains, so "cfd" PTO gains are an error).

    Output¶

    out/validated_case/<name>/
├── <name>.json           ← copy of the config used (read back by run_metric)
├── run.log
├── models/
│   └── <model>/model.json        ← copy of each model definition used
├── data/
│   └── <group>_<label>.csv       ← simulated time series per (wave, model, solver)
└── wave/                         ← synthetic waves only
    ├── <group>_wave_ts.csv       ← t, eta, eta_rec
    ├── <group>_wave_recon.csv    ← components A, w, k, phi
    └── <group>_wave_param.json   ← generation parameters, water depth, J, depth type, wave length

    run_metric adds metric/, plots/ and metric.log to the same folder.

    naming¶

    • run label: <model> | <method> <dt> <interp>, where <interp> gives the interpolation of restoring, excitation and cfd as lin / cub / nul (e.g. lin | RK4 0.05 linlinlin)
    • group: the CFD case label (e.g. Hs2p2_Te6p6_d120000_k-430000_example), or synthetic_<wave_type>_Hs<H>_Te<T> for a synthetic wave
    • CSV: <group>_<label>.csv with the label made file-safe, e.g. Hs2p2_Te6p6_d120000_k-430000_example_lin_RK4_0_05_linlinlin.csv. For a synthetic wave, the group is followed by the PTO gains of the model, _d<damping>_k<stiffness> (_d0_k0 without PTO), e.g. synthetic_irr_Hs2p0_Te6p5_d120000_k0_lin_syn_RK4_0_05_linlinlin.csv

    time series (data/*.csv)¶

    Every column is on the solver time grid, clipped to the valid window. The model columns depend on its force terms (see Model):

    Column Units Description
    t s Time
    x, xdot m, m/s Displacement and velocity
    eta m Wave elevation
    specific columns N One column per force term, e.g. fhs_lin, fr_damp, f_fk_lin, fd_lin, f_fk_nl_x, f_visc, cfd_<column>
    fr_lin N Total radiation force (fr_damp − ma_inf·ẍ), with a radiation term
    F_static, F_exc, F_rad, F_drag N Role columns, same name in every model (zeros if the category is absent)
    F_hyd N Total fluid force, comparable to the CFD fhyd_cfd
    fs_pto, fd_pto, fpto N PTO spring, damper and total force
    Pabs, Pd, Ps W Absorbed, damper and spring power
    sim_time s Wall-clock integration time (constant column)
    time_ratio — Simulated physical time / sim_time (constant column)

    Notes¶

    Time margins — t_warmup (start) and t_causal (end) are derived from the model definitions and BEM data, not JSON inputs. Radiation state_space: 30 s warmup (states start at 0). Linear convolution (fk or diffraction linear_conv): t_irf[-1] warmup and |t_irf[0]| causal (±30 s with the F2T IRF). The largest margins across the models of a run are applied to every simulation, so all models are compared on the same window. time_ratio uses the full simulated duration.

    dt mismatch — if a solver dt differs from the CFD reference dt, the script warns and asks to continue. The metrics are computed on the coarser of the two grids.
