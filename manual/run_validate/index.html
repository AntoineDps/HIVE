    Input Config Reference¶

    All scripts are driven by JSON config files. This page lists every field for each script.

    Handle config¶

    Path: inputs/handle_case/<name>.json

    {
  "wave_type": "regular",
  "cut_time": [50, 0],
  "duration": null,
  "hydro_sphere_pkl": "r5",
  "dt": 0.05,
  "cases": [
    {
      "T": 8.0,
      "H": 2.0,
      "damping": 120000,
      "stiffness": -280000,
      "plot": true
    }
  ],
  "plot_options": {
    "sea_state": true,
    "power": true,
    "dynamics": true,
    "hydro": false,
    "3d": false,
    "variable": ["fe_lin", "x"]
  }
}
    Field Type Description
    wave_type string "regular" or "irregular"
    cut_time [float, float] Seconds to cut from [start, end]
    duration float | null If set, truncates to this duration after cut
    hydro_sphere_pkl string BEM pickle filename (without .pkl) in models/bem/
    dt float | null Resample timestep [s]. Null keeps original
    cases list One entry per CFD case
    cases[].T float Wave period [s]
    cases[].H float Wave height [m]
    cases[].damping float PTO damping [N s/m]
    cases[].stiffness float PTO stiffness [N/m]
    cases[].plot bool Include in plots (default true)
    plot_options dict Which plots to generate

    Validate config¶

    Path: inputs/validate_case/<name>.json

    {
  "models": [
    {"name": "linear"},
    {"name": "linear_viscous"}
  ],
  "wave_sources": [
    {"type": "cfd_case", "case_name": "example"}
  ],
  "solvers": [
    {"method": "RK4", "dt": 0.05, "interpolation": {}}
  ],
  "eta_inputs": [
    {"type": "true"}
  ],
  "simulation": [
    {"type": "closed_loop"}
  ],
  "plot_options": {
    "states": true,
    "forces": false
  }
}
    Field Type Description
    models list[dict] Models to validate; each entry has a "name" key matching a folder under models/
    wave_sources list[dict] Wave data sources; "cfd_case" loads a handled CFD case by "case_name"
    solvers list[dict] One or more solver configurations to run (see below)
    eta_inputs list[dict] Wave elevation input type; "true" uses the measured elevation
    simulation list[dict] Simulation mode; "closed_loop" includes PTO feedback
    plot_options dict Which plots to generate

    Solver config¶

    Each entry in solvers has the following fields:

    Field Type Description
    method string "RK4", "RK2", or "euler"
    dt float Integration timestep [s]
    interpolation dict Per-force-term interpolation flags (see below)

    interpolation¶

    The precomputed force signals (\(f_e^{lin}\), nonlinear FK force, wave elevation) are evaluated on the handled data grid. During ODE integration, sub-stage evaluations may fall between grid points. The interpolation dict controls, for each force term, whether it is re-evaluated at every RK sub-stage or frozen to the value at the start of the step (zero-order hold).

    The underlying grid interpolation is always piecewise linear.

    Key Force term Effect when true
    "fe" Linear excitation force \(f_e^{lin}\) Evaluated at each RK sub-stage
    "fk" Nonlinear Froude–Krylov force Evaluated at each RK sub-stage
    "eta_hs" Wave elevation for nonlinear hydrostatic Evaluated at each RK sub-stage

    Setting a key to false freezes that term within each timestep (ZOH), which is cheaper but reduces effective accuracy for that term. An empty dict {} enables interpolation for all terms and is recommended for RK4 and RK2.

    "interpolation": {}                        // all terms interpolated (default)
"interpolation": {"fe": false}             // freeze excitation force, interpolate rest
"interpolation": {"fe": false, "fk": false} // freeze both, interpolate eta_hs only
    Field Type Description
    scheme string Identification scheme: "viscous_drag", "pi_gain", or "linear_si"
    base_model string Folder name under models/ for the base physics model. Use "none" for linear_si.
    waves_train list[str] Handle config stems to use as training data
    scheme_params dict Scheme-specific parameters (see below)
    solver dict Solver configuration — same fields as validate config (see above)

    viscous_drag scheme params¶

    Field Description
    c_v_range [min, max] search range for \(c_v\) [N s²/m²]
    n_points Number of grid points
    objective Objective name (default "nrmse_x")

    pi_gain scheme params¶

    Field Description
    Kp_range [min, max] for proportional gain
    Ki_range [min, max] for integral gain
    n_points Grid resolution per dimension

    linear_si scheme params¶

    Field Description
    signal_file Path to signal CSV (relative to code/)
    input_signals List of input column names
    output_signals List of output column names
    identification "frequency" (VF) or "time" (N4SID)
    w_start, w_end Frequency range for fitting [rad/s]
    order_list List of VF pole orders to sweep
    tau_min, tau_max, n_tau Causality delay sweep parameters
    smooth_window ETFE smoothing window length
    num_block_rows N4SID block rows (Hankel matrix size)

    Validate config¶

    Path: inputs/validate_case/<name>.json

    {
  "models": [
    {"name": "linear"},
    {"name": "linear_viscous"}
  ],
  "wave_sources": [
    {"type": "cfd_case", "case_name": "example"}
  ],
  "solvers": [
    {"method": "RK4", "dt": 0.05, "interpolation": {}}
  ],
  "eta_inputs": [
    {"type": "true"}
  ],
  "simulation": [
    {"type": "closed_loop"}
  ],
  "plot_options": {
    "states": true,
    "forces": false
  }
}
    Field Type Description
    models list[str] Model folder names under models/
    solver.method string "RK4", "RK2", or "euler"
    solver.dt float Integration timestep [s]
    solver.interpolation dict Interpolation scheme for forcing signals (see below)

    solver.interpolation¶

    The excitation force \(f_e^{lin}\) and wave elevation are precomputed on the handled data grid. At each ODE stage the solver evaluates them at intermediate time points via interpolation. The interpolation dict is passed to scipy.interpolate.interp1d:

    "interpolation": {}               // default — linear interpolation
"interpolation": {"kind": "linear"}   // same as above, explicit
"interpolation": {"kind": "nearest"}  // zero-order hold (step function)
"interpolation": {"kind": "cubic"}    // cubic spline, smoothest
    kind value Behaviour
    "linear" Piecewise linear (default, recommended)
    "nearest" Zero-order hold — holds value at nearest grid point
    "quadratic" Quadratic spline
    "cubic" Cubic spline — smoothest, highest cost

    Using "nearest" with RK4 reduces the effective accuracy of the forcing term to first order. "linear" is a good default for all solver methods. See Models & Solvers — Forcing signal interpolation for a full discussion.

    run_validate¶

    Output root: models/<model_name>/validation/

    models/<model_name>/validation/
├── result.json               ← metric summary for all models and sea states
├── run.log
├── data/
│   └── <label>_simrun.csv    ← simulated time series per case per model
└── plots/
    ├── scatter_<metric>.png / .pkl
    └── timeseries_<label>.png / .pkl

    result.json structure¶

    {
  "t_warmup": 15.0,
  "t_causal": 3.2,
  "models": {
    "linear": {
      "T8_H2": { "nrmse_x": 0.12, "mean_P_abs": 430.5 },
      "T10_H3": { ... }
    }
  }
}

    Metric names¶

    Metrics passed in the metrics list of validate and identify configs follow this pattern:

    Name Description
    nrmse_x NRMSE on displacement
    nrmse_xdot NRMSE on velocity
    rmse_x RMSE on displacement [m]
    rmse_xdot RMSE on velocity [m/s]
    mean_P_abs Mean absorbed power [W]

    See Metrics for definitions.
