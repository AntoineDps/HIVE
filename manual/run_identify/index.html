    run_identify¶

    Identifies model parameters or data-driven surrogates from CFD reference data using a pluggable scheme system.

    Run¶

    first run¶

    python -m script.run_identify --case <name>.json

    Config files <name>.json live in inputs/identify_case/. The filename stem becomes the output folder name under source/models/.

    rerun options¶

    When the output folder already exists, the script prompts:

    [1] erase and redo
[2] stop, do nothing
[3] load saved figures     — reopen existing .pkl plots interactively
[4] save with date suffix  — run and save under <name>_YYYYMMDD (keeps existing folder)

    Option [4] is useful to keep previous identification results while running a new one.

    what it does¶

    1. Loads the base model definition from source/models/<base_model>/model.json
    2. Creates a DDFeed — loads training data and runs scheme.prep()
    3. Creates an Optimizer — owns simulation helpers and delegates to scheme.run()
    4. Computes time margins (t_warmup, t_causal) from the base model and BEM data
    5. Saves identified parameters, result JSON, simulation CSVs and plots to source/models/<name>/identification/

    Scheme: viscous_drag¶

    Identifies the quadratic drag coefficient \(c_v\) in \(F_{visc} = -c_v |\dot{x}| \dot{x}\).

    input JSON config¶

    {
  "scheme": "viscous_drag",
  "base_model": "linear",
  "waves_train": ["example_cases", "other_cases"],
  "scheme_params": {
    "type": ["force", "response"],
    "search": ["opt", "grid"],
    "base_force": "fhyd_lin",
    "c_v_min": 0,
    "c_v_max": 5000,
    "n_points": 50,
    "objective": "rmse_x"
  },
  "solver": {
    "method": "rk4",
    "dt": 0.05,
    "interpolation": {"fe": false, "fk": false, "eta_hs": false}
  }
}

    scheme_params fields¶

    Field Type Default Options / values Description
    type string or list — "force" · "response" · or both as a list Identification type. "force" fits \(c_v\) to match \(f_{hyd}\); "response" fits \(c_v\) to match \(x\), \(\dot{x}\)
    search string or list — "opt" · "grid" · or both as a list Search method. "opt" uses a bounded scalar optimiser; "grid" sweeps a uniform grid over \([c_{v,min},\ c_{v,max}]\)
    base_force string "fhyd_lin" any column present in the DataHandle dataset Reference BEM force column subtracted when type = "force"
    c_v_min float 0.0 any non-negative float [N·s²/m²] Lower bound of the \(c_v\) search range
    c_v_max float 5000.0 any positive float [N·s²/m²] Upper bound of the \(c_v\) search range
    n_points int 100 any positive integer Grid resolution — used only when search = "grid"
    objective string or dict "rmse_x" see Objectives Metric used to score \(c_v\) candidates in "response" methods

    The four possible type × search method combinations are: force_opt, force_grid, response_opt, response_grid. Pass lists to run several at once.

    The objective field accepts a string shorthand or a dict with an explicit direction override:

    "objective": "rmse_x"
"objective": {"name": "mean_P_abs", "direction": "maximize"}
    Name Description Default direction
    "rmse_x" RMSE of displacement \(x\) minimize
    "rmse_xdot" RMSE of velocity \(\dot{x}\) minimize
    "nrmse_x" Normalised RMSE of \(x\) minimize
    "nrmse_xdot" Normalised RMSE of \(\dot{x}\) minimize
    "mean_P_abs" Mean absorbed power \(P_{abs}\) maximize
    "rmse_P_abs" RMSE of absorbed power minimize

    Per-case vs global identification¶

    For every method, viscous_drag always produces two \(c_v\) values:

    • per-case — \(c_v\) fitted independently to each wave case (captures sea-state variability)
    • global — single \(c_v\) fitted across all cases pooled together → written to model.json

    JSON output¶

    {
  "scheme": "viscous_drag",
  "objective": {"name": "rmse_x", "direction": "minimize"},
  "results": {
    "force_opt": {
      "c_v_global": 1850.0,
      "metric_global": 0.09,
      "metric_label": "rmse_x",
      "c_v_per_case": {"case_label_1": 1700.0, "case_label_2": 1950.0},
      "metric_per_case": {"case_label_1": 0.07, "case_label_2": 0.11},
      "c_v_mean": 1825.0,
      "c_v_std": 125.0
    }
  }
}

    Scheme: pi_gain¶

    Identifies per-sea-state PI controller gains \((B_{pto},\ K_{pto})\) that maximise an objective (default: mean absorbed power).

    input JSON config¶

    {
  "scheme": "pi_gain",
  "base_model": "linear",
  "waves_train": [
    {"type": "cfd_case", "case_name": "example_cases"},
    {"type": "synthetic", "T": 7.0, "H": 2.0, "duration": 120.0}
  ],
  "scheme_params": {
    "method": ["analytical", "grid"],
    "B_min": 0,
    "B_max": 1000000,
    "K_min": -1000000,
    "K_max": 1000000,
    "n_B": 20,
    "n_K": 20,
    "objective": {"name": "mean_P_abs", "direction": "maximize"},
    "stability": {"enabled": true, "r": 5.0},
    "n_jobs": -1
  },
  "solver": {
    "method": "rk4",
    "dt": 0.05,
    "interpolation": {}
  }
}

    waves_train entry fields¶

    Each dict in waves_train must have a "type" key:

    "type": "cfd_case" — load from a handled CFD folder

    "type": "synthetic" — generate a synthetic wave signal on the fly:

    Wave supports the following fields:

    Field Type Default Options / values Description
    type string — "synthetic" Source type selector
    wave_type (→ Wave.type) string "reg" "reg" (regular sinusoid) · "irr" (irregular JONSWAP) Wave type
    T float — any positive float (s) Wave period (regular) or peak period (irregular)
    H float — any positive float (m) Wave height (regular) or significant wave height (irregular)
    gamma float None any positive float JONSWAP peak enhancement factor — used only when wave_type = "irr"
    t_end (→ duration) float 100.0 any positive float (s) Signal duration
    dt float 0.01 any positive float (s) Time step — taken from solver.dt
    w_end float 8.0 any positive float (rad/s) Upper limit of frequency axis
    dw float 0.01 any positive float (rad/s) Frequency resolution

    scheme_params fields¶

    Field Type Default Options / values Description
    method string or list "opt" "analytical" · "opt" · "grid" · or a list of several Identification method(s). Pass a list to run and compare multiple methods in one execution
    B_min float 0.0 any float [N·s/m] Lower bound for \(B_{pto}\) search
    B_max float 1e6 any float [N·s/m] Upper bound for \(B_{pto}\) search
    K_min float -1e6 any float [N/m] Lower bound for \(K_{pto}\) search
    K_max float 1e6 any float [N/m] Upper bound for \(K_{pto}\) search
    n_B int 20 any positive integer Grid points along \(B\) axis — used only when method = "grid"
    n_K int 20 any positive integer Grid points along \(K\) axis — used only when method = "grid"
    B_init float midpoint of [B_min, B_max] any float [N·s/m] Initial value for the "opt" optimiser
    K_init float midpoint of [K_min, K_max] any float [N/m] Initial value for the "opt" optimiser
    objective string or dict {"name": "mean_P_abs", "direction": "maximize"} see Objectives Metric used to score \((B, K)\) candidates
    stability dict {"enabled": false, "r": 5.0} enabled: true / false · r: float (m) Early-stop check: aborts integration if \(\|x - \eta\| > r\). r defaults to buoy radius if not set
    n_jobs int 1 any integer · -1 = all CPU cores Parallel workers for "grid" search via joblib

    "analytical" requires that cfd_case entries carry wave parameters (Te). It derives gains from BEM data directly without running any simulation.

    The objective field accepts a string shorthand or a dict with an explicit direction override:

    "objective": "rmse_x"
"objective": {"name": "mean_P_abs", "direction": "maximize"}
    Name Description Default direction
    "rmse_x" RMSE of displacement \(x\) minimize
    "rmse_xdot" RMSE of velocity \(\dot{x}\) minimize
    "nrmse_x" Normalised RMSE of \(x\) minimize
    "nrmse_xdot" Normalised RMSE of \(\dot{x}\) minimize
    "mean_P_abs" Mean absorbed power \(P_{abs}\) maximize
    "rmse_P_abs" RMSE of absorbed power minimize

    JSON output¶

    {
  "scheme": "pi_gain",
  "base_model": "linear",
  "objective": {"name": "mean_P_abs", "direction": "maximize"},
  "stability": {"enabled": true, "r": 5.0},
  "n_cases": 12,
  "results": {
    "grid": {
      "B_per_case": {"case_label": 42000.0},
      "K_per_case": {"case_label": -15000.0},
      "metric_per_case": {"case_label": 1250.3},
      "metric_label": "mean P_abs [W]"
    }
  }
}

    Multiple entries¶

    Field Accepts list? Effect
    waves_train yes (all schemes) entries pooled into one training dataset
    type + search yes (viscous_drag) cartesian product → one pass per combination
    method yes (pi_gain) one pass per value
    solver no single solver shared across all passes — run separate config files to compare solvers

    All entries in waves_train are loaded and merged into a single flat pool of wave cases. Identification runs on all of them together — there is no separate pass per entry.

    For viscous_drag, the global \(c_v\) is optimised over the concatenated signal from all cases at once, and each case also gets its own per-case \(c_v\). Adding more entries widens the training distribution.

    For pi_gain, gains are always per sea state — each loaded wave case gets its own optimal \((B_{pto}, K_{pto})\). Adding more entries simply extends the set of sea states covered.

    Other keys¶

    Field Type Options / values Description
    base_model string folder name under source/models/ — currently: "linear" · "none" disables physics Base physics model to augment with viscous drag
    waves_train list[string] stems of folders under data/handled/ Training cases. Multiple entries are pooled into one dataset
    scheme_params dict see table below Scheme-specific parameters
    solver dict see table below Forward simulation settings

    solver:

    Field Type Default Options / values Description
    method string "rk4" "euler" · "rk2" · "rk4" (case-insensitive) ODE integration scheme
    dt float — any positive float (s) Fixed timestep
    interpolation dict {} keys: "fe", "fk", "eta_hs" — values: true / false Per-force-term interpolation flags. Empty dict disables all
    ---

    Outputs structure¶

    source/models/<name>/
├── <name>.json               ← copy of the config used
├── model.json                ← model definition updated with identified parameters
├── run.log
└── identification/
    ├── result.json           ← identified parameters and objective value per method
    ├── data/
    │   └── *.csv             ← simulated time series at best parameter values
    └── plots/
        ├── *.png
        └── *.pkl             ← interactive figure snapshots
