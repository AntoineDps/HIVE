    run_identify¶

    Identifies model parameters or data-driven surrogates from CFD reference data using a pluggable scheme system.

    Usage¶

    python -m script.run_identify --case <name>.json

    Config files <name>.json live in inputs/identify_case/. The filename stem becomes the output folder name under source/models/.

    rerun options¶

    When the output folder already exists, the script prompts:

    [1] erase and redo
[2] stop, do nothing
[3] load saved figures     — reopen existing .pkl plots interactively
[4] save with date suffix  — run and save under <name>_YYYYMMDD (keeps existing folder)

    Option [4] is useful to keep previous identification results while running a new one.

    what it does¶

    1. Loads the base model definition from source/models/<base_model>/model.json
    2. Creates a DDFeed — loads training DataHandle objects and runs scheme.prep()
    3. Creates an Optimizer — owns simulation helpers and delegates to scheme.run()
    4. Computes time margins (t_warmup, t_causal) from the base model and BEM data
    5. Saves identified parameters, result JSON, simulation CSVs and plots to source/models/<name>/identification/

    Input JSON config¶

    {
  "scheme": "viscous_drag",
  "base_model": "linear",
  "waves_train": ["example_cases"],
  "scheme_params": {
    "c_v_range": [0, 5000],
    "n_points": 50,
    "objective": "nrmse_x"
  },
  "solver": {
    "method": "RK4",
    "dt": 0.05,
    "interpolation": {}
  },
  "plot_options": {
    "grid": true,
    "timeseries": true
  }
}

    top-level fields¶

    Field Type Description
    scheme string Identification scheme to use (see available schemes below)
    base_model string Folder name under source/models/ for the base physics model. Use "none" for linear_si
    waves_train list[string] Handle config stems whose processed data are used as training cases. e.g. ["example_cases"] loads data/handled/example_cases/
    scheme_params dict Scheme-specific parameters (see per-scheme tables below)
    solver dict Solver settings used for forward simulations during identification
    plot_options dict Controls which plots are generated (see below)

    solver fields¶

    Field Type Description
    method "RK4" Integration method
    dt float Simulation timestep (s)
    interpolation dict Per-force-term interpolation flags: {"fe": bool, "fk": bool, "eta_hs": bool}

    plot_options fields¶

    Field Type Description
    grid bool Objective function grid plot (viscous_drag / pi_gain only)
    timeseries bool Simulated vs CFD time series at best parameter values

    Available schemes¶

    scheme key What it identifies
    viscous_drag Quadratic drag coefficient \(c_v\) via grid search
    pi_gain PI controller gains \(K_p\), \(K_i\) via 2D grid search
    linear_si \(\eta \to f_e\) and \(f_e \to \dot{x}\) state-space models via VF or N4SID

    viscous_drag scheme params¶

    Field Type Description
    c_v_range [float, float] Search range [min, max] for \(c_v\) [N·s²/m²]
    n_points int Number of grid points
    objective string Objective metric (default: "nrmse_x")

    pi_gain scheme params¶

    Field Type Description
    Kp_range [float, float] Search range [min, max] for proportional gain
    Ki_range [float, float] Search range [min, max] for integral gain
    n_points int Grid resolution per dimension

    Outputs¶

    source/models/<name>/
├── <name>.json               ← copy of the config used
├── model.json                ← model definition updated with identified parameters
├── run.log
└── identification/
    ├── result.json           ← identified parameters and objective value
    ├── data/
    │   └── *.csv             ← simulated time series at best parameter values
    └── plots/
        ├── grid_*.png / .pkl
        └── timeseries_*.png / .pkl

    result.json structure¶

    {
  "c_v": 1850.0,
  "objective": "nrmse_x",
  "value": 0.09,
  "t_warmup": 15.0
}

    Notes¶

    • The base model must exist at source/models/<base_model>/model.json before running.
    • t_warmup and t_causal are computed automatically from the base model and applied to all simulation clips.
    • For linear_si, the scheme loads its own signal data (SELF_LOADING = True) and does not use CFD DataHandle objects — waves_train is unused.
